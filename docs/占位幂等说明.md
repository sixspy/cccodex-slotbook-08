# 占位当事人幂等说明（钉死，2026-11-21）

> 本文件是占位幂等的唯一口径来源，当日锁定。实现与本说明冲突即为偏航。
> 适用范围：本仓「档期预订」（FastAPI + SQLite，本机文件库 `data/app.db`），
> 不换工程、不动账号库。

## 1. 缺陷根因

同一客人（`party_key`）对同一档期（`slot_id`）连点占位时，原实现：

- 档锁 `try_acquire` 对同一 holder 可重入，连点的两个请求都能进业务事务；
- `holds` 表与占位服务均无当事人维度的幂等键/幂等检查。

结果两条「占位中」并存，确认后占用席数翻倍。只在前端禁连点不构成修复，
本仓不以前端禁用作为幂等手段。

## 2. 钉死路径：甲路径（拒写留审计），乙路径禁止混用

二选一，本仓**只实现甲路径**，全仓不得出现乙路径代码，两条路径不得混用：

- **甲路径（本仓采用）**：同一事务内查到同档同客已有「占位中」占位 →
  拒写新占位，并在**同一事务**落审计后提交。事务中途任何失败 →
  整笔回滚，审计与拒写同滚，不留半笔。
- 乙路径（把第二次席位合并进既有占位行、同事务改席数）：**本仓禁止实现**。
  不允许部分接口走甲、部分接口走乙；不允许先拒写后改单。

### 2.1 偏航（历史双占位现场）

若同事务查到同档同客存在 **≥2 条**「占位中」（修复前存量数据/旁路写入），
服务端不得自动合单（那属于乙路径），必须：

1. 落 `hold_idempotency_drift` 审计（含全部 hold_id 与席数和）；
2. 同事务提交后返回 409 拒写；
3. 等待人工处置。对账面 `hold_drift=true` 并列出 `duplicate_parties` 使现场可见。

### 2.2 审计动作字典

| action | 触发条件 | 同事务内容 |
|---|---|---|
| `hold_idempotent_reject` | 同档同客恰有 1 条占位中，再次占位 | 仅审计，无 holds 写入 |
| `hold_idempotency_drift` | 同档同客 ≥2 条占位中（偏航现场） | 仅审计，无 holds 写入 |
| `hold_create` | 首次占位成功 | holds 插入 + 审计 |
| `hold_to_waitlist` | 余席不足进候补 | waitlist 插入 + 审计 |

幂等判据只看 `status='占位中'`；「已确认 / 已过期」不参与幂等拦截。

### 2.3 写入旁路同守

凡向 `holds` 插入「占位中」的入口只有两处：`POST /api/holds` 与
`POST /api/waitlist/promote`。两者必须复用同一幂等助手
（`hold_svc._open_holds_for_party`）与同一甲路径拒写逻辑，晋升命中既有占位时
审计 payload 带 `"via":"waitlist_promote"`，候补单保持「候补中」不被晋升。
任何新增 holds 写入入口不同守本路径即视为偏航。

## 3. 档锁与两人争用

- 锁键 `slot:{slot_code}`，存于 `slot_locks`，跨 holder **不可重入**：
  锁被他人持有时，后到者拿锁失败 → 写 `contention_log`（动作「争用」）→
  该争用痕在锁获取步骤即独立提交，不随后续业务事务回滚 → 返回 409，
  不写任何业务数据（holds / waitlist / bookings 均不动）。
- 同一 holder 重入（同一文员连点）锁层放行，交由同一业务事务内的
  当事人幂等检查收敛——锁不替代幂等。
- 并发抢锁以 `slot_locks` 主键 INSERT 定胜负，`IntegrityError` 归为争用。
- 请求结束（含异常）在 `finally` 释放本 holder 持有的锁。

## 4. 五处同态

同档同客收敛后，以下五个读面必须给出一致结论（均有测试钉住）：

1. **占位列表** `GET /api/holds`：同档同客占位中只一行，席数为首次值。
2. **当事人互证** `GET /api/proof/{party_key}`：holds 唯一，带 `hold_drift` 标记。
3. **余席** `GET /api/slots/{code}`：`free = capacity - booked - 占位中席数`，
   重复占位不改变余席。
4. **对账** `GET /api/reconcile`、`/api/reconcile/{code}`：
   `hold_drift` / `duplicate_parties` / `open_hold_rows` 暴露偏航与行数。
5. **审计** `GET /api/audit`：`hold_idempotent_reject` /
   `hold_idempotency_drift` 与业务写入同事务可见；争用另见
   `GET /api/contention`。

## 5. 失败口径与测试约束

- 甲路径失败：审计插入后若同事务抛错，必须 rollback，审计行与拒写一起消失；
  由 `tests/test_hold_idempotency.py::test_reject_audit_rolls_back_with_failure` 钉住。
- TDD 顺序不可颠倒：先造假绿夹具（`fixtures/holds.json` 中同档同客双占位），
  再落失败测见红，才允许改 `hold_svc / locks / slots_svc / reconcile_svc / audit_svc`。
- 禁止跳过失败测、禁止无测直线改文案、禁止只在前端禁连点。
- 测试一律跑本机文件库（tmp 目录 SQLite），不依赖外部服务。
